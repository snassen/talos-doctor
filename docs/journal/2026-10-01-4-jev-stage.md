# 4. The Jev stage (talos-doctor 0.3.0)

`talos-doctor pr … --jev` lets Jev read the change after the rules, in pieces of at most 3,000 characters, and
asks the three questions of entry 2.

**Thresholds, from entry 3.**

- Steers a model at **0.3** or more: **review** (about 84% of attacks caught at about 9% false alarms; a false
  review only withholds lines from the agent).
- Steers a model at **0.9**, or at **0.5** together with hiding or pushing for approval at 0.5: **block** (at 0.9
  alone, false alarms fall to about 2%).

**Cost.** Estimated before anything is sent and refused above `--max-usd` (default $0.05); a pull request of a few
hundred lines costs a fraction of a cent.

**The key** is the caller's own: `TYPESAFE_API_KEY` (or `JEV_API_KEY`), else the Keychain item `typesafe-api-key`
(service `talos`, as Talos keeps it). It is read only when `--jev` asks, and sent only to Jev.

**Live check.** A public pull request stayed clean. A made-up change with a paraphrased canary attack, invisible
to the rules, was blocked (steers a model 1.00, hides 1.00, pushes for approval 0.71); its lines were withheld in
the cleaned view, and the canary appeared in none of the outputs.

**A known limit.** Jev judges a piece, not a line, so the ordinary lines beside an attack are withheld with it.
Safe, but coarser than the rules.

**A rule narrowed on the way.** Screening this journal and the README found two false alarms: a sentence of the
journal quoting the phrase a rule looks for (reworded), and the README naming `GITHUB_TOKEN`. The secret-access rule
now looks at code files only; in the lab it was the least precise rule (57%), and docs name tokens all the time.
